# Orientador de Estudos

Reuni quatro cenários de orientação tecnológica para verificar apresentação, explicação de conceitos, dicas graduais de programação e planejamento de estudos. O resultado é um registro de comportamento e critérios de avaliação; este repositório não contém uma aplicação executável.

## Cenários

1. Apresentação: descrever formas concretas de apoio e pedir o objetivo de estudo.
2. Conceito: explicar uma skill como procedimento reutilizável, com analogia e pergunta de compreensão.
3. Prática: dar uma dica inicial sobre um acumulador, sem entregar o código corrigido.
4. Planejamento: distribuir uma trilha Python de exemplo em quatro semanas, reservando prática e revisão.

[Síntese dos casos](interacoes.md) · [Critérios e limites](validacao.md)

## Como avaliar

Leia os casos e compare as respostas com os critérios em `validacao.md`. Para repetir a avaliação em um orientador de sua escolha, forneça os mesmos objetivos e dados de exemplo. Resultados podem variar. Não há teste automatizado distribuído neste repositório nem medição de aprendizagem pessoal.

O cronograma usa hipóteses explícitas: nível intermediário, cinco sessões semanais de uma hora durante quatro semanas. As20 horas planejadas incluem prática e revisão; não representam agenda, presença ou horas realizadas por uma pessoa.

## Decisões e aprendizado técnico

Separei dados do cenário, critérios observáveis e limites. Uma resposta bem escrita não comprova consulta ao catálogo, execução de código ou leitura automática de arquivos. Uma dica pode preservar espaço para raciocínio; uma pergunta aberta só é útil quando a resposta posterior é realmente examinada.

Os casos foram avaliados em uma rodada. Adaptação ao longo de várias interações, execução de exercícios e acompanhamento de progresso continuam fora desta verificação.
